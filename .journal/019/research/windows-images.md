## Recommendation

- For both Windows images, use **distrobuilder 3.3.1 `repack-windows` only to inject pinned VirtIO drivers into a Microsoft ISO**, then perform the unattended install in a real Incus VM and capture it with native `incus publish`; `repack-windows` produces another ISO, not an Incus VM image ([distrobuilder 3.3.1, 2026-02-24](https://github.com/lxc/distrobuilder/releases/tag/v3.3.1), [official tutorial](https://linuxcontainers.org/distrobuilder/docs/latest/tutorials/use/)).
- Run GitHub Actions as the **orchestrator**, but run Windows Setup on a dedicated Incus 7.4 cluster member/project, not under nested QEMU inside a runner VM. Standard private-repository runners have only 2 CPU, 8 GB RAM, and 14 GB SSD, while Windows 11 requires at least 2 vCPU, 4 GB RAM, and a 64 GB disk ([GitHub runner table](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [Microsoft VM requirements](https://learn.microsoft.com/en-us/windows/whats-new/windows-11-requirements#virtual-machine-support)).
- `incus-gh-runner` is suitable for that orchestration job, but **not for the inner Windows VM as currently deployed**: its policy explicitly sets `security.nesting: "false"` ([deployment.cue:371-386](/Users/josh/code/meigma/incus-gh-runner/deploy/incus/cue/deployment.cue#L371-L386)).
- Put recipes, answer files, PowerShell provisioning/finalization, expected component versions, artifact URLs, and SHA-256 values in Git; keep Microsoft media and credentials out of Git. Distrobuilder otherwise downloads VirtIO from a moving `latest-virtio` URL when `--drivers` is omitted, so always pass a verified driver ISO ([source](https://github.com/lxc/distrobuilder/blob/main/distrobuilder/main_repack-windows.go)).
- Build Windows 11 with UEFI Secure Boot and an Incus TPM 2.0 device; build Server 2025 as **Server Core**. Microsoft requires Secure Boot capability and a virtual TPM for supported Windows 11 VMs; Server Core is the documented headless installation option ([Windows 11 requirements](https://learn.microsoft.com/en-us/windows/whats-new/windows-11-requirements#virtual-machine-support), [Incus TPM device](https://linuxcontainers.org/incus/docs/main/reference/devices_tpm/), [Server 2025 evaluation](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2025)).
- Generalize with Sysprep `/generalize /oobe /mode:vm /shutdown /quiet`, never boot the golden source again, and smoke-test a fresh clone; `/quiet` is mandatory on Server Core ([Microsoft Sysprep options](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/sysprep-command-line-options?view=windows-11)).
- Export the Incus VM as split metadata plus qcow2, publish those as imgoci `amd64/incus/incus-vm` roles `metadata` and `disk` through BigOCI to a **private** GHCR repository, and attest the release-index digest ([Incus split format](https://linuxcontainers.org/incus/docs/main/reference/image_format/#split-tarballs), [imgoci format](/Users/josh/code/imgoci/spec/README.md#L1-L18)).
- Incus does not consume imgoci directly: a last-mile controller must resolve and digest-verify the two roles, call `incus image import metadata.tar.xz rootfs.img --alias …`, launch-smoke-test the new fingerprint, then move the stable catalog alias ([Incus import commands](https://linuxcontainers.org/incus/docs/main/howto/images_copy/#import-from-the-local-file-system), [imgoci non-goals](/Users/josh/code/imgoci/spec/README.md#L139-L147)).

## Concrete Windows pipeline

### Repository layout and pins

```text
images/windows/
  pins.lock.yaml                 # exact versions, URLs, SHA-256, license/source IDs
  common/
    instance.yaml                # Incus build-VM/profile settings
    bootstrap.ps1                # one ordered provisioning entry point
    finalize.ps1                 # cleanup, verification, Sysprep
    smoke.ps1
  windows-11-desktop/
    Autounattend.xml             # installation/audit passes
    deploy-unattend.xml          # specialize/oobeSystem for clones
    ultravnc.inf                 # silent installer response/config
  windows-server-2025/
    Autounattend.xml             # selects Server Core
    deploy-unattend.xml
.github/workflows/windows-images.yml
```

`pins.lock.yaml` should record: Microsoft product/edition/build and the official ISO SHA-256; distrobuilder 3.3.1 and its release SHA-256; an exact virtio-win ISO URL/version/SHA-256; exact Cua Driver version plus installer-script commit/hash and downloaded asset hash; exact VNC installer/hash; explicitly selected CAB/MSU updates and hashes; and a recipe schema/revision. Microsoft publishes a SHA-256 list for the current Windows 11 Enterprise 25H2 evaluation ISO ([evaluation page, “Verify Download”](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise)); the existing runner-image guide independently establishes the same exact-version, checksum, finished-image checksum, attestation, and boot-test pattern ([build-runner-images.md:111-155](/Users/josh/code/meigma/incus-gh-runner/docs/docs/how-to/build-runner-images.md#L111-L155)). Do not run an unconstrained Windows Update during a supposedly reproducible build; update the pinned MSU set in a reviewed PR instead.

### Workflow steps

1. **Cheap validation on GitHub-hosted CI.** Validate the lock schema, verify that every downloaded input has a SHA-256, validate answer files with a pinned Windows SIM/ADK job when available, and pin all Actions by full commit SHA. Do not place media, product keys, local-user passwords, VNC credentials, or Incus client keys in Git.
2. **Acquire and repack.** A dedicated privileged Linux builder with ample scratch space downloads licensed media from a controlled cache, checks every hash, and runs pinned distrobuilder with explicit `--drivers`, `--windows-version w11` or `2k25`, and `--windows-arch amd64`. Source inspection shows repack uses WIM/hivex/ISO tools and injects drivers into the boot/install WIMs; it does not boot QEMU ([repack source](https://github.com/lxc/distrobuilder/blob/main/distrobuilder/main_repack-windows.go), [driver set](https://github.com/lxc/distrobuilder/blob/main/windows/drivers.go)).
3. **Create payload/answer media.** Build a small read-only ISO whose root contains `Autounattend.xml` and the pinned payload. Windows Setup searches removable media roots for that exact name and caches answer files across reboots; finalization must delete cached answer files because Microsoft warns they can retain sensitive data ([Setup automation](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-automation-overview?view=windows-11#use-an-answer-file-while-installing-windows), [sensitive-data section](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-automation-overview?view=windows-11#sensitive-data-in-answer-files)).
4. **Install on the Incus cluster, not inside the runner.** The orchestration job uses narrowly scoped Incus credentials and a dedicated image-build project to create an empty VM on a designated member. Set `image.os=Windows…`; attach the repacked installer ISO, answer/payload ISO, and the Incus Agent CD (`source=agent:config`); attach a TPM to Windows 11 and keep Secure Boot enabled. Incus documents the empty-VM/ISO flow and says the Agent CD must remain attached on every boot to refresh credentials ([Windows VM install](https://linuxcontainers.org/incus/docs/main/howto/instances_create/#launch-a-vm-that-boots-from-an-iso), [Agent CD](https://linuxcontainers.org/incus/docs/main/howto/instances_create/#install-the-incus-agent-into-virtual-machine-instances)). The eventual runtime profile, not the disk image artifact, must therefore retain the Agent CD and Windows 11 TPM/Secure-Boot settings.
5. **Guest provisioning.** Use one `FirstLogonCommands` entry that launches `bootstrap.ps1`; Microsoft now starts all such commands concurrently despite their “SynchronousCommand” name ([FirstLogonCommands](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-firstlogoncommands)). For Server 2025, select Server Core, install the Incus Agent, apply pinned servicing, and install no Cua/VNC/desktop software; Microsoft defines Server Core as the headless, no-local-GUI option ([Server 2025 page](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2025)).
6. **Desktop session contract.** For Windows 11, create the dedicated lab automation user, arrange an interactive console logon, install the exact pinned Cua version as that user, then run `cua-driver autostart enable` and `kick` from that interactive session. This is required because Incus exec, like SSH, originates outside the interactive desktop; Cua documents that GUI APIs see no windows in Session 0, while its Interactive-logon scheduled task places the daemon in Session 1+ and exposes `\\.\pipe\cua-driver` to the Session-0 CLI ([Cua Windows session guide](https://cua.ai/docs/how-to-guides/driver/windows-ssh.md)). Configure the VNC fallback as a boot service so it can reach pre-login screens; treat it as an isolated fallback, not the automation transport.
7. **Generalize and capture.** Remove setup media and secrets/caches, verify expected installed versions and Incus Agent behavior, ensure the OS volume is not left encrypted against the build VM’s TPM, then run `%WINDIR%\System32\Sysprep\Sysprep.exe /generalize /oobe /mode:vm /shutdown /quiet /unattend:C:\image\deploy-unattend.xml`. Microsoft requires `/generalize` even for identical hardware, and `/mode:vm` requires the same hypervisor/hardware profile ([Sysprep options](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/sysprep-command-line-options?view=windows-11)). Once stopped, do not boot the source again; publish it, export with `incus image export <fingerprint> <dir> --vm`, and retain both the immutable fingerprint and checksums ([Incus export](https://linuxcontainers.org/incus/docs/main/howto/images_manage/#export-an-image-to-a-file)).
8. **Clone smoke gate.** Launch a new VM from the captured fingerprint with the production profile. Require a fresh SID/hostname, successful `incus exec`, Cua daemon status in Session 1+, a real `list_windows` or screenshot call through the named pipe, and VNC availability at the login screen for Windows 11; require Incus exec and absence of Desktop Experience for Server Core. Delete the clone after the gate. Microsoft notes that per-user Microsoft Store updates can make Sysprep fail, so do not mutate Store apps during the bake ([Sysprep generalize guidance](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/sysprep--generalize--a-windows-installation?view=windows-11#microsoft-store-apps)).
9. **Publish to GHCR/imgoci.** Publish the split metadata and qcow2 as one release index with selectors `architecture=amd64`, `target=incus`, `representation=incus-vm`, roles `metadata` and `disk`; use BigOCI for a disk too large for a dependable single registry blob. Publish an immutable version/date tag, resolve it back by digest, verify decoded bytes, and attach provenance to the release-index digest. imgoci/go already supports publish/fetch/resolve, digest-verifies each file, and supports BigOCI, but its API is pre-v1, so pin an exact module version ([imgoci/go README](/Users/josh/code/imgoci/go/README.md#L1-L17), [compatibility](/Users/josh/code/imgoci/go/README.md#L55-L67)).
10. **Last mile and promotion.** A cluster-side importer resolves the GHCR reference by digest, fetches the complete `metadata`+`disk` role set into private staging, calls `incus image import metadata.tar.xz rootfs.img --alias windows/11/desktop-<build>` (or `windows/server-2025-<build>`), smoke-launches that exact fingerprint, then replaces the stable alias only after success. Incus supports both unified single-file and split two-file imports ([Incus import docs](https://linuxcontainers.org/incus/docs/main/howto/images_copy/#import-from-the-local-file-system)); retain the prior fingerprint/tag so rollback is an alias move, not a rebuild.

## Risks and unknowns

- **Windows redistribution/licensing is unresolved and release-blocking.** Microsoft’s evaluation downloads establish 90-day Windows 11 and 180-day Server 2025 test rights, not permission to redistribute derived qcow2 images through GHCR ([Windows 11 evaluation](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise), [Server evaluation](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2025)). Microsoft’s reimaging guidance ties standard-image rights to Commercial Licensing and matching product/version/edition/language rights ([Reimaging rights](https://www.microsoft.com/licensing/guidance/Reimaging-rights)). Keep GHCR private, and do not publish even privately until the license owner confirms both registry storage/distribution and every launched VM’s entitlement. Evaluation images are unsuitable as the durable production catalog because they expire and eventually shut down.
- **Cua post-Sysprep behavior is unverified.** The design requires the daemon at logon ([agentcompute.md:154-163,206-211](/Users/josh/code/lab2/.wt/feat-agentcompute-design/docs/docs/designs/drafts/agentcompute.md#L154-L163)); whether the per-user Interactive scheduled task survives Sysprep/generalization and starts after cloned OOBE was not established in Cua or Microsoft documentation. Make a fresh-clone GUI call a hard promotion gate; if it fails, have the deployment answer’s single first-logon bootstrap recreate the task idempotently. The served `install.ps1` supports a version variable, but no `Get-FileHash`/checksum validation was found in that script; pin and validate both the installer content and release asset outside it ([installer](https://cua.ai/driver/install.ps1)).
- **VNC choice needs a bake-off.** TigerVNC explicitly says its Windows `winvnc` server is currently unmaintained and may not function, so reject it ([TigerVNC README](https://github.com/TigerVNC/tigervnc/blob/master/README.rst)). UltraVNC is active and documents silent `/loadinf` installation, but an exact release artifact, hash, Windows 11 25H2 login/secure-desktop behavior, and service hardening were not verified ([UltraVNC repository](https://github.com/ultravnc/UltraVNC), [installer switches](https://uvnc.com/docs/ultravnc-server/48-ultravnc-installation.html)). Pin a tested installer and restrict its listener to the sandbox management path; cloned shared VNC/autologon credentials are high-value secrets.
- **TPM/BitLocker clone state needs proof.** Windows 11 24H2 broadened automatic device encryption, while the Incus TPM is software TPM 2.0 ([BitLocker overview](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/), [Incus TPM](https://linuxcontainers.org/incus/docs/main/reference/devices_tpm/)). Confirm `manage-bde -status` is fully decrypted before capture and that every launched VM obtains independent TPM state; never bake a disk sealed to the build VM’s TPM. Exact Incus profile/device-copy behavior for this recipe remains unverified until the clone smoke test.
- **Capacity and duration are unmeasured.** The only grounded Windows 11 floor is 2 vCPU, 4 GB RAM, and 64 GB disk ([Microsoft requirements](https://learn.microsoft.com/en-us/windows/whats-new/windows-11-requirements#virtual-machine-support)). Start the spike at 4 vCPU/8 GiB/80–100 GiB for desktop, 2–4 vCPU/4–8 GiB/64 GiB for Server Core, and at least 100 GiB temporary builder storage, but mark those recommendations and build-duration estimates **UNVERIFIED** until benchmarked on IncusOS storage. Serialize Windows image builds initially because capture/compression and multi-GB GHCR transfer are I/O-heavy.
- **No maintained end-to-end Windows-to-Incus builder was found that is both permissively licensed and eliminates the native Incus install step.** Packer is maintained but BUSL; the Packer Incus plugin starts from an existing Incus image rather than an empty Windows ISO flow; `antifob/incus-windows` has no detected license/releases; ADK/DISM and Microsoft’s Server VHD still require conversion, first boot, Agent installation, Sysprep, and Incus packaging ([Packer license](https://github.com/hashicorp/packer/blob/main/LICENSE), [Incus plugin](https://developer.hashicorp.com/packer/integrations/bketelsen/incus/latest/components/builder/incus), [`incus-windows`](https://github.com/antifob/incus-windows), [DISM](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/what-is-dism?view=windows-11)).
